# 《敲到成佛》开发设计方案

> 依据 `prd.md` 落地。定位:个人开发者可执行的 V1.0 完整方案,并为 V2.0 预留扩展。
> 原则:手感第一、配置驱动、数据先行、快速上线。

---

## 一、体验设计:敲击手感是第一优先级

### 1.1 核心交互链路

```
手指按下 → 判定(200ms 内连续点按=连击) → 计算功德 → 三重反馈 → 状态更新 → 节流存档
```

三重反馈(缺一不可,这是"手感"的定义):
1. **视觉**:木鱼本体下压变形(scaleY 0.9,100ms 回弹) + 功德飘字 + 光晕涟漪
2. **听觉**:敲击音(可合成,见音频方案) + 音色随皮肤切换
3. **触觉**:wx.vibrateShort 轻微震动(可开关,安卓可用 `type: 'heavy'`)

### 1.2 反馈节奏规范

| 反馈 | 规格 |
|---|---|
| 飘字 | 每次敲击必出,上浮 40px 渐隐 600ms;连击≥10 飘"法喜充满"(金色) |
| 连击文案 | 10/50/100 三档,含专属音效 |
| 连击保护 | 中断前 1.5s 出现渐隐光晕提示,引导玩家维持节奏 |
| 防连击策略 | touchend 计数 + 每帧至多结算 1 击;连续两次敲击间隔 <80ms 视为同一击抖动合并(80ms 严格防抖会吃掉快速敲击手感,真机验证阈值) |
| 震动 | 默认开;iOS 仅短震动,安卓可选强震动 |

## 二、数值设计方案

### 2.1 功德产出模型

```
单次功德 = 1 × (1 + 皮肤加成 + 功法加成)
```

- 基础:1 功德/敲
- 皮肤加成:+5% / +10% / +15% / +20%(见 PRD 3.3);注意后期(百万级)百分比加成被稀释,建议皮肤附带二级属性(离线收益+X%、连击保护时长+X),让付费点全程有价值
- 功法加成:V2.0 生效,预留乘法位
- 连击**不直接加功德**,只影响情绪反馈与事件触发概率——避免"无脑狂敲"破坏禅意氛围

### 2.2 境界成长曲线(时间测算)

假设日常玩家日均敲击 800~1500 下(含离线收益补足):

| 境界 | 累计功德 | 预期到达时间 | 说明 |
|---|---|---|---|
| 凡夫 | 0 | 0 | 新手期 |
| 居士 | 1,000 | 1 天 | 首个正反馈,皮肤+1 解锁 |
| 比丘 | 10,000 | 1 周 | 音色变化,留存中期 |
| 罗汉 | 100,000 | 4~6 周 | 解锁离线禅修(转折点) |
| 菩萨 | 1,000,000 | 3~4 个月 | 配合转生循环 |
| 佛 | 10,000,000 | 8~12 个月 | 终极目标,靠涅槃加速 |

> 提示:数值需灰度调参。V1.0 先开放至"比丘",观察 7 日留存后再定罗汉成本。

### 2.3 离线禅修(罗汉解锁)

```
离线功德 = 等效 300 次敲击/小时 × 境界系数,上限 12 小时
```

- 无加成:300 功德/小时,12h 上限 = 3,600 功德/夜
- 受功法「华严经·法界观」影响:+100%(V2.0)
- 领取时看广告可翻倍(商业化点位,见第四节)
- 防作弊:离线时长以服务端记录 `lastSeenAt` 计算,客户端只做展示

### 2.4 经济总表(功德产出与消耗)

| 项目 | 产出/消耗 | 频率 |
|---|---|---|
| 手动敲击 | +1 基础/次 | 任意 |
| 离线禅修 | +300/h(罗汉) | 每日 1 次 |
| 随机事件·佛光普照 | 30s 功德×2 | 概率触发 |
| 功德钥匙(开功法副本) | 消耗 | 每日广告获取 2 把 + 初始 3 把 |
| 皮肤/场景兑换 | 5,000~100,000 | 一次性 |

## 三、节奏副本与谱面设计(V2.0,结构先行)

### 3.1 谱面数据格式(JSON,配置驱动)

```json
{
  "id": "xinjing",
  "name": "心经",
  "bpm": 72,
  "duration": 90,
  "difficulty": 1,
  "tracks": [
    { "t": 1.0,  "type": "tap",  "pos": 0.5 },
    { "t": 1.5,  "type": "hold", "pos": 0.3, "dur": 0.8 },
    { "t": 2.4,  "type": "slide","from": 0.2, "to": 0.8 },
    { "t": 3.0,  "type": "tap",  "pos": 0.7 }
  ]
}
```

- 音符类型:单点(tap) / 长按(hold) / 滑动(slide),与 PRD 对应
- 判定窗口:Perfect ±50ms / Good ±120ms / Miss
- 无谱面预览,用"光晕预警"(落点前 0.8s 出现光晕),保持 PRD 的"听经参悟"氛围
- 谱面文件放分包或 CDN,按境界解锁动态加载

### 3.2 难度曲线

| 经文 | 解锁 | 音符密度 | 判定容错 |
|---|---|---|---|
| 心经 | 初始 | 1.2 音/s | 宽松(教学) |
| 大悲咒 | 居士 | 1.8 音/s | 标准 |
| 金刚经 | 比丘 | 2.5 音/s | 标准 |
| 楞严咒 | 罗汉 | 3.2 音/s | 严格 |
| 华严经 | 菩萨 | 4.0 音/s | 严格 |

### 3.3 评价与奖励(对齐 PRD)

无上正觉(全连) → 功法效果 +20%;明心见性(>95%) → 习得;初窥门径(>80%) → 习得无加成;杂念纷飞 → 失败不消耗钥匙(V1.0 内不做,进 V2.0)。

## 四、商业化方案

### 4.1 关键约束(必须先知道)

- **个人主体无法开通虚拟支付(内购)**,只能广告变现(流量主)。
- 若后续想上内购/月卡,需升级企业主体。因此 V1.0 商业化 = **激励视频广告为主**,内购作为企业主体后的 V2.0 规划。

### 4.2 激励视频点位(全部放在"领取/解锁"按钮,不打断敲击)

| 点位 | 内容 | 频率限制 |
|---|---|---|
| 随喜功德 | 今日功德翻倍 | 每日 3 次 |
| 离线收益翻倍 | 领取离线功德时 ×2 | 每日 1 次 |
| 佛光普照延长 | 事件时长 +30s | 事件触发时 1 次 |
| 功德钥匙 | 获得开副本钥匙 | 每日 2 次 |
| 皮肤限免试用 | 限时体验限定皮肤 | 每日 1 次 |

### 4.3 广告填充与体验原则

- 首次进入后 60s 内不展示任何广告,维持"禅意"入场
- 广告按钮统一文案化,但**避开宗教献金类字眼**("随喜""供养""添灯油"暗示功德箱/香火钱,易踩宗教类审核红线),改用中性词:"静心加成""禅茶一盏""添一缕香"
- 广告频次上限:每日 ≤6 次,超限后按钮置灰提示"明日再来"

### 4.4 企业主体后(V2.0 可选)

- 功德钥匙礼包、菩提子直购、禅修月卡(离线上限+专属音色+去广告)

## 五、技术实现方案

### 5.1 技术选型

| 层 | 方案 | 理由 |
|---|---|---|
| 游戏框架 | **微信原生小游戏(Canvas 2D + TypeScript)** | 玩法=点击+UI+音效+轻量动画,无引擎依赖;包体最小、启动最快;个人开发者可控;不引入引擎学习成本 |
| 渲染 | Canvas 2D 自绘,自研轻量 UI 树(Button/Text/Panel/ScrollList) | 小游戏无 DOM;自研 UI 满足本项目面板场景足够 |
| 音频 | 敲击音用 **WebAudio 振荡器合成**(省包体),BGM 用 InnerAudioContext 流式播放 | 木鱼"咚"可合成:约 180Hz 正弦 + 60ms 衰减包络;iOS 需首次触摸后才激活 AudioContext(首个点击前静默属正常);BGM 流式加载、切换淡入淡出;遵循静音键(obeyMuteSwitch) |
| 后端 | 微信云开发(云函数 + 云数据库 + 云存储) | 免运维、openid 免鉴权、天然抗爬;离线时长与防刷放云函数 |
| 排行榜 | 开放数据域(subContext + sharedCanvas) | 微信唯一官方方案,仅渲染好友榜 |
| 分享卡片 | Canvas 离屏绘制 → 生成图片转发 | 每日一偈、境界突破卡 |

> 备选:若 V2.0 特效量(粒子、光效、谱面动画)超出原生舒适区,再评估迁移 Cocos Creator 3.x,当前阶段不做引擎前置投资。

### 5.2 工程结构

```
mind_tap/
├── spec/                 # 文档(prd.md / design.md)
├── game/                 # 小游戏工程
│   ├── game.js / game.json / project.config.json
│   ├── src/
│   │   ├── main.ts               # 入口:场景调度
│   │   ├── core/                 # GameLoop / EventBus / Storage / AudioMgr / Share
│   │   ├── scenes/               # Boot / Home(敲击) / Cultivate(境界) / Setting
│   │   ├── systems/              # MeritSystem / ComboSystem / OfflineSystem / SkinSystem
│   │   ├── ui/                   # 按钮/飘字/面板/连击条
│   │   ├── data/                 # 配置:skins.json / scenes.json / sutras.json(谱面)
│   │   └── utils/                # 格式化/时间/缓动
│   ├── audio/                    # BGM、合成音效脚本
│   └── cloud/                    # 云函数:login / syncProfile / offlineCalc / rank
│       └── open-data/            # 开放数据域(排行榜渲染)
└── docs/
```

### 5.3 数据模型(云数据库)

```
users:   { _openid, nickname, avatarUrl, createdAt }
profiles:{ _openid, merit, level(境界), totalTaps,
           skinId, sceneId, bgmId, soundOn, vibrateOn,
           inventory:{skins:[], scenes:[], bgms:[]},
           lastSeenAt, offlineClaimedAt, settings }
```

- 本地:wx.setStorage 全量镜像(秒开离线可用);云端为权威副本
- 合并策略:登录时拉云端,取"本地未同步增量 ∪ 云端"字段级合并
- 防刷:敲击功德计数由云函数批量结算(本地攒 N 次后上报),不逐次请求
- **弱网/首启容错(必须)**:启动时云函数登录设 2.5s 超时,失败即入"游客模式"本地可玩,后台静默重试、联网后自动同步;严禁启动流程阻塞在登录上——首次体验卡顿是留存杀手

### 5.4 性能与包体

- 主包目标 < 1.5MB(代码 + 核心素材),BGM 全走分包/CDN 流式
- 音频内存:同一时刻仅 1 首 BGM + 音效池(≤8 实例,LRU 回收)
- 粒子/光效用对象池,避免频繁 GC 卡顿
- **机型适配**:敲击区避开刘海/安全区(wx.getWindowInfo().safeArea);低端机降帧渲染、减少粒子;按需渲染(无动画帧跳过)

## 六、V1.0 开发里程碑(个人开发者,约 4~6 周)

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0 资质启动(并行) | 申请软著(个人可办,常规 30~60 工作日,可加急 1~3 天)+ 小程序备案(免费) | 与 M1 同时启动,不占开发时间但占日历时间;提审前必须齐 |

| M2 敲击手感 MVP | 点击判定、木鱼变形回弹、飘字、合成音效、震动 | 连续敲击 2 分钟无卡顿,手感自测达标 |
| M3 数值与境界 | 功德结算、六境界、突破动画与音效、连击文案 | 数据流打通,里程碑反馈强烈 |
| M4 皮肤/场景/音频 | 3 皮肤、2 场景、3 首 BGM、音色切换、白噪音叠加 | 切换无延迟,内存稳定 |
| M5 离线与存档 | 离线禅修(罗汉)、本地存档、云同步、防刷结算 | 杀进程重进数据不丢,换机可恢复 |

## 七、风险与合规

1. **经文版权**:佛教经典多为公有领域,但**唱诵录音有版权**——V1.0 使用无版权素材或合成禅意氛围音,商用录音需授权
2. **宗教内容审核**:标题与文案避开"迷信""祈福必应"等表述;不做真实捐款/宗教活动引导;以"文化符号+心理疗愈"定位,通过率更高
3. **虚拟支付资质**:个人主体无内购,见第四节;提审前确认主体类型
4. **广告合规**:广告容器规范接入流量主,按钮文案避免诱导点击
5. **数据合规**:收集用户信息前弹窗授权;openid 不落客户端日志
6. **上线资质**:见第六节 M0——无软著与备案无法提审;流量主需累计 UV≥1000 才可开通,前期先养量
7. **内容安全**:榜单/分享中的用户昵称头像需过 msgSecCheck 安全检测;头像昵称使用官方"头像昵称填写能力"获取

## 九、评审修订与补充(V1.1,2026-08-07)

以"个人开发者 + 微信真实上线流程"视角评审,修复/补充以下内容(正文相应位置已同步修改):

### 9.1 上线前置流程(新增,最重要)

| 前置项 | 说明 | 时间 | 启动时机 |
|---|---|---|---|
| 软件著作权 | 微信小游戏提审必需;个人可申请,常规 30~60 工作日,加急 1~3 天(约数百元) | 1~8 周 | **M1 立即启动** |
| 小程序/小游戏备案 | 工信部要求,个人主体可办,免费 | 1~2 周 | 与软著并行 |
| 流量主 | 累计 UV ≥ 1000 后可开通广告 | 上线后 | 先养量再开广告 |

> 教训:资质是日历时间不是开发时间,必须与开发并行,否则"开发完干等一个月"。

### 9.2 美术资源策略(新增,个人开发者最大风险)

- V1.0 定"极简扁平禅意风":低饱和色板 + 几何造型,UI/木鱼/场景**代码绘制(Canvas 矢量)**,不依赖外部图片素材
- 木鱼/光效/飘字程序化生成;场景用"底色+渐隐元素"分层,代码即可出效果
- 皮肤差异 = 换色板 + 换音色(成本最低);金乌流光等复杂特效留 V2.0
- 如需位图(AI 生成),统一滤镜后入配置表,单张 < 200KB

### 9.3 V1.0 留存钩子补强("每日功课"必须进 V1.0)

原 V1.0 日留存只有离线收益 + 每日一偈,对放置游戏不够。补:

- **每日功课**(简化早课晚课):每日敲满 100 下 → 领"精进宝箱"(随机功德/菩提子),7 日全勤送限定挂饰
- 实现成本低(本地计数 + 日期戳),但显著拉 3 日留存

### 9.4 新手引导(新增)

- 首启 3 步引导:敲一下 → 看飘字/音效 → 打开境界页,总时长 < 30s,可跳过
- 首个里程碑(居士)做"突破演出":慢镜头 + 专属音效 + 金色飘字,这是新手留存的关键奖励时刻
- 常驻目标指引:境界页显示"距下一境界还差 X 功德"

### 9.5 分享钩子与物料规范(新增)

- **V1.0 就要"分享得功德"**:每日首次分享 → 双方各 +100 功德,否则分享率极低
- 分享卡规范:昵称 + 境界徽章 + 偈语 + 大按钮"来敲一下";5:4 尺寸;离屏绘制注意 iOS 中文渲染需等字体就绪(loadFontFace 或系统字体)

### 9.6 埋点(新增)

- 轻量事件:启动 / 敲击时长 / 境界突破 / 广告点击 / 分享成功,走云开发统计
- 上线首周重点:首日转化、3 日留存、广告 eCPM——决定后续数值与商业化迭代

### 9.7 开放数据域技术坑(排行榜)

- **上传频控**:wx.setUserCloudStorage 有频控,改为"每 30s 或每次结算后节流上传",禁止每次敲击上传
- **字体**:开放数据域无法加载自定义字体,排行榜用系统字体
- **头像昵称**:新版基础库用"头像昵称填写能力",开放数据域内不取 getUserInfo
- 好友榜只展示"自己也上传过分数"的好友,需先引导用户敲几下再进榜
