# 《敲到成佛》上线部署方案

> 版本:V1.0 | 2026-08-08 | 配套:`prd.md`(两期需求)、`tech-design.md`(技术方案)、`test-plan.md`(测试方案)
> 范围:微信小游戏 + 云开发后端,个人开发者,渐进式两期发布。

## 一、部署架构总览

```
┌──────────────────────────────────────────────────────┐
│  微信客户端                                           │
│  ┌──────────────────┐   ┌──────────────────┐        │
│  │  主域(游戏逻辑)    │   │  开放数据域(排行榜) │        │
│  └────────┬─────────┘   └────────┬─────────┘        │
│           │ wx.cloud.callFunction│                   │
└───────────┼──────────────────────┼───────────────────┘
            │                      │
    ┌───────▼──────────────────────▼────────────┐
    │  微信云开发(同一环境)                        │
    │  ┌─────────┐  ┌───────────┐  ┌──────────┐ │
    │  │ 云函数   │  │ 云数据库   │  │ 云存储    │ │
    │  │ login   │  │ users     │  │ BGM 分包  │ │
    │  │ syncPro │  │ profiles  │  │ 分享卡模板 │ │
    │  │ offline │  │ events    │  └──────────┘ │
    │  │ daily   │  │           │               │
    │  │ rank    │  │           │               │
    │  └─────────┘  └───────────┘               │
    └───────────────────────────────────────────┘
```

**环境说明**:
- 个人开发者一个云环境即可,不区分 dev/staging/production
- 一期用云开发免费额度(按量计费)
- 环境 ID 不可更改,创建时确认:`kxcf-prod`(建议)

## 二、环境准备(一次性配置)

### 2.1 微信公众平台

| 步骤 | 操作 | 备注 |
|---|---|---|
| 1 | 登录[微信公众平台](https://mp.weixin.qq.com) → 注册小程序 | 选择"小游戏"类目,个人主体 |
| 2 | 完善基本信息:名称"敲到成佛"、头像、介绍 | 名称需查重(已确认可用) |
| 3 | 开发 → 开发设置 → 获取 AppID | 记入 `project.config.json` |
| 4 | 开发 → 开发设置 → 服务器域名 | 云开发自动填充,无需手动配置 |
| 5 | 设置 → 基本设置 → 小程序备案 | 等软著受理通知后提交(见 launch-checklist.md) |

### 2.2 云开发环境

| 步骤 | 操作 | 关键点 |
|---|---|---|
| 1 | 微信开发者工具 → 云开发 → 开通 | 创建环境 `kxcf-prod`,按量付费(免费额度够初期) |
| 2 | 数据库 → 创建集合 | `users`、`profiles`、`events` |
| 3 | 数据库 → 权限设置 | 所有集合设为**"仅创建者可读写"**(云函数用管理员权限) |
| 4 | 数据库 → 索引 | `profiles`:按 `_openid` 唯一索引 + 按 `merit` 倒序索引 |
| 5 | 云函数 → 上传 | 逐个上传 login/syncProfile/offlineCalc/dailyClaim/rank |

### 2.3 开发者工具初始化

```bash
# 在微信开发者工具中
# 1. 打开项目 mind_tap/game/
# 2. 点击"云开发"图标 → 确认环境 ID
# 3. 在 project.config.json 中配置:
{
  "appid": "你的AppID",
  "cloudfunctionRoot": "cloud/",
  "cloudbaseRoot": "cloud/",
  "cloud": {
    "envId": "kxcf-prod"
  }
}
# 4. game.js 首行调用 wx.cloud.init({ env: "kxcf-prod", traceUser: true })
```

## 三、构建与发布流程

### 3.1 构建链路(一期无需打包工具)

```
TypeScript 源码(game/src/)
      │
      ▼
微信开发者工具(TS 工程,自动编译)
      │
      ▼
云函数(cloud/*) → 右键"上传并部署:云端安装依赖"
      │
      ▼
单击"预览" → 真机调试(开发阶段)
      │
      ▼
单击"上传" → 开发者后台生成开发版
      │
      ▼
设置为体验版(内测用)
      │
      ▼
提交审核 → 审核通过 → 发布上线
```

### 3.2 版本号规范

采用 `主.次.修订` 语义化版本:

| 版本 | 含义 | 示例 |
|---|---|---|
| 主版本号 | 大功能上线(第二期) | 2.0.0 |
| 次版本号 | 新功能/新里程碑 | 1.1.0(新皮肤)、1.2.0(功法) |
| 修订号 | Bug 修复/数值调参 | 1.0.1、1.0.2 |

一期版本线:`1.0.0`(首次提交) → `1.0.x`(审核反馈修复)

### 3.3 云函数部署命令

每个云函数目录下必须有 `package.json` 和 `index.js`:

```
cloud/
├── login/
│   ├── index.js           # 云函数主逻辑
│   ├── package.json       # { "dependencies": { "wx-server-sdk": "latest" } }
│   └── config.json        # (可选)环境变量
├── syncProfile/
│   ├── index.js
│   └── package.json
├── offlineCalc/
├── dailyClaim/
└── rank/
```

部署方式:在开发者工具中右键云函数文件夹 → **"上传并部署:云端安装依赖"**

> **不用 npm install 本地再上传**:选"云端安装依赖"会自动在云端执行 npm install,省事且避免本地 Node 版本不一致。

### 4.1 集合结构(上线前执行)

**users 集合**:
```json

  "updatedAt": "Date"
```

```json
// 权限:仅创建者可读写

{
  "_openid": "auto",
```

**events 集合**:

### 4.2 索引创建(云开发控制台执行)

```
profiles._openid    → 唯一索引(已默认)
profiles.merit      → 倒序索引(用于排行榜,开放数据域读取)
events._openid      → 普通索引(便于后台查询)
events.ts           → 倒序索引
```

| 上线监控 | 上线后 7 天 | 崩溃率、留存、eCPM 数据回收 | ☐ |

| 阶段 | 操作 |
|---|---|

| 场景 | 流程 |
|---|---|

## 六、灰度发布策略

### 6.1 灰度节奏(首次上线)

```
Day 1: 5% 流量(新用户) → 观察 4h
  ├─ 崩溃率 <0.5%? → 是 → 继续
  └─ 否 → 回滚,定位问题

Day 1~2: 5% → 观察 24h
  ├─ 首日转化 ≥70%? 无 P0 投诉? → 是 → 扩大
  └─ 否 → 维持 5%,分析数据

Day 2: 20% → 观察 12h
Day 3: 50% → 观察 12h
Day 4: 全量
```

> 实际灰度比例以微信后台支持为准(最低可能是 5%/10% 等阶梯)。**保守比激进好**:一个完美启动窗口比修线上事故重要得多。

### 6.2 灰度观察指标

| 指标 | 阈值 | 异常动作 |
|---|---|---|
| JS 崩溃率 | <0.5% | 超过回滚 |
| 接口错误率(云函数 5xx) | <1% | 超过暂停灰度 |
| 首日转化(注册→首次敲击) | ≥70% | 低于 50% 排查新手引导 |
| 举报/投诉 | 0 | 有则立即排查(内容合规) |

### 6.3 灰度配置

在微信公众平台 → 版本管理 → 灰度发布中设置:

```
全量发布:☐(先不勾)
按比例灰度:5% → 逐步提升
按条件灰度:可选"新用户"(二期功能灰度用)
```

## 七、回滚方案

### 7.1 代码回滚(紧急)

**微信后台 → 版本管理 → 线上版本 → "版本回退"**

- 微信支持直接回退到上一个线上版本
- 回退后用户端会在下次启动时自动拉取旧版本
- 回退期间云函数保持最新(如果 Bug 在云函数,需单独回滚云函数)

### 7.2 云函数回滚

云开发控制台 → 云函数 → 选择函数 → 版本管理:

- 每个云函数保留最近 3 个版本
- 出问题时直接切换到上一版本
- 修复后上传新版本并重新切换

### 7.3 数据库修复

**不直接操作线上数据库**(除非必须):

| 场景 | 操作 |
|---|---|
| 数值配置错误(如功德产出翻倍) | 修改云数据库配置文档或云函数常量,无需回滚客户端 |
| 脏数据修正 | 写一个临时云函数批量修正,执行后删除 |
| 数据恢复 | 云数据库自动备份(免费版每日 1 次),可回档到指定时间点 |

### 7.4 回滚决策表

| 线上现象 | 响应时间 | 动作 |
|---|---|---|
| 闪退率 > 1% | 立即 | 回滚代码版本 |
| 云函数 100% 超时 | 立即 | 回滚云函数版本 |
| 广告无法加载 | 2h 内 | 优先换广告位 ID;不行再发版 |
| 排行榜空白 | 4h 内 | 检查开放数据域;紧急修复发版 |
| 留存明显低于预期 | 次日 | 分析数据后再决策(非紧急) |

## 十、云开发成本估算

| 资源 | 免费额度(个人版) | 预估一期消耗 | 月费(超出后) |
|---|---|---|---|
| 云函数调用次数 | 10 万次/月 | 1~3 万次(以 DAU 500 计) | 0.0133 元/万次 |
| 云函数资源量(GBs) | 4 万 GBs/月 | <1 万 GBs | 0.00011108 元/GBs |
| 云数据库读/写 | 5 万次/天(读)、3 万次/天(写) | 远低于免费额度 | 写 0.015 元/万次 |
| 云存储容量 | 5GB | BGM 分包约 5~10MB | 0.0043 元/GB/天 |
| CDN 流量 | 5GB/月 | <1GB | 0.18 元/GB |

> **结论**:一期 DAU 500 以内免费额度绰绰有余;即使 DAU 破万,月费也在几十元级别。

## 十一、FAQ——个人开发者常见翻车点

| 问题 | 答案 |
|---|---|
| **云函数超时怎么设?** | syncProfile/offlineCalc 设 10s,其他设 5s;在云函数 `config.json` 中配 `"timeout":10` |
| **云函数需要配 VPC 吗?** | 不需要,默认公网即可 |
| **真机调试看不到云函数调用?** | 确认 `wx.cloud.init` 环境 ID 正确;确认手机微信版本 ≥8.0 |
| **上传代码包体积超了?** | 检查 node_modules 是否被误打进包(在 `project.config.json` 排除) |
| **审核被驳回最多的原因?** | 名称不符/缺乏游戏介绍/功能过于简单/宗教敏感文案 |
| **灰度发布找不到设置?** | 必须在"已发布"状态下才能设置灰度;审核通过后先不要点"全量发布" |
| **云开发免费额度用完了怎么办?** | 自动按量计费,余额不足会停服;建议充值 50 元备用 |
